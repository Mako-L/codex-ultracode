Use the built-in native workflow tool for a user-requested workflow or enabled Ultracode keyword/session. The engine is shipped with Codex; no plugin installation, skill lookup, portable MCP discovery, or shell-launched orchestrator is required.

Call tools.workflow through code-mode with at least one nonempty selector: script (inline JavaScript), scriptPath (existing file), name (saved workflow), or resumeFromRunId (prior native run). Optional fields are args (JSON input), title and description (strings), and concurrency (integer 1–16). Do not pass model, effort, action, polling, or wait fields to this tool. Model and effort belong to each agent() call.

Write ordinary JavaScript with top-level await and a final return. Start every script with its first and only export: a literal export const meta = {name:'review', description:'Review supplied files'}. Both name and description are required. Metadata names and descriptions must be nonempty strings. For saving as a command, choose a safe filename: 1–64 lowercase letters, digits, or hyphens, starting with a letter or digit. Available functions are agent(prompt, options), parallel([() => task, ...]), pipeline(items, ...stages), phase(name), and log(value); args contains the supplied JSON input. agent() returns text, or JSON when options.schema is supplied. Options include label, model, effort, schema, phase, agentType, and isolation. Use advertised Codex models and efforts; choose gpt-5.6-luna at low effort for routine workers when available, and preserve explicit user choices. Workers inherit the parent permissions; isolation:'worktree' requests a separate Git worktree for edits. Scripts cannot import modules, read files, run shell commands, or use current time/randomness. Put external operations in authorized workers. Limits are 16 simultaneous workers, 1,000 workers per run, and 4,096 items per fan-out. Workers cannot recursively launch workflows. Check null worker results and retained errors before claiming success.

Use optional meta.title for a readable workflow title. For a multi-phase workflow, declare meta.phases as objects such as [{title:'Inspect', detail:'Read the requested files'}, {title:'Review', detail:'Check the resulting changes'}]. These titles and details appear in the consent summary. Call phase('Inspect') or phase('Review') with the matching title before that group of work. A phase model annotation describes intent; actual model routing remains in each agent() call.

For example, when gpt-5.6-luna is advertised:
const result = await tools.workflow({script:"export const meta = {name:'review', description:'Review the requested files'}; return await agent('Inspect the requested files and report concrete findings', {model:'gpt-5.6-luna', effort:'low'});"}); text(result);

The native host validates source and requests consent. Do not call portable workflow_validate, workflow_run, workflow_inspect, or workflow_wait for this run. Print the returned result. After a successful asynchronous launch receipt, acknowledge launch and finish the current parent turn. The run ID is not a worker thread ID. A typed workflow.completion message arrives automatically and resumes the parent; report results from that evidence. Do not poll threads or call workflow again to wait. Cancellation or source-validation failure ends this launch: report the returned result without retrying or switching hosts.

Use native /workflows for user-requested inspection, pause/resume, stop, worker restart, and saving. Saved scripts live in project .codex/workflows or CODEX_HOME/workflows (normally ~/.codex/workflows); optional plugins may provide additional named templates. Native run state belongs to the originating parent thread. Preserve source-preview consent and parent authority across launch and resume.
